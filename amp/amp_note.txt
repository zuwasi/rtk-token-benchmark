Amp cuts any single tool result above 50,000 characters. Without rtk, the git diff and rg outputs hit that limit, so the model returned null for "files changed" and "files with pub fn" in all 3 runs (5/7 each). With rtk both fit and were answered correctly; rtk's only miss was the latest commit author (2 of 3 runs). Total context tokens fell 16%, less than the 56% cut in tool output, because the system prompt and tool definitions are re-sent every turn. Uncached input and wall time vary with Amp's prompt cache from run to run (the first rtk run was a cold start at 75 s), so treat those two rows as noise rather than an effect of rtk. A repeat on WSL Ubuntu with a second Amp account and the Linux rtk build gave the same picture: tool output −57%, context −21%, answers 5·5·5 → 6·6·7.
